## 0. 실행 대원칙 (모든 Phase 공통 — 위반 금지)

1. **소울 재선언**: 새 표면 하나하나가 "조용히 서로의 선함을 목격하는 곳"을 강화해야 한다. 비교·랭킹·1등·거대숫자 단독노출·"OO님보다"는 **어디에도 금지**. 파장·기여는 *겨루는 점수가 아니라 이야기*.
2. **정체성 매핑**: 4가지 방 종류(solo/cheered/closed/open) × 새 기능 = 항상 4종 일관성 검토.
3. **배포 순서 = migration 먼저**. 미적용 상태로 EF/OTA 배포 시 컬럼 부재로 기존 기능까지 깨진 전례 다수(CLAUDE.md 참조). 새 마이그레이션 번호는 **0054부터** 이어서.
4. **자동 테스트 의무 영역**(결제·AI검수·인증/권한·박제·유배지·도전인연 ×횟수)을 건드리면 `__tests__/`에 검증 함께. 나머지는 tsc 0 + 실기기 안내.
5. **디자인 토큰**(`mobile/lib/tokens.ts`)만 사용. 색·여백·폰트 밖에서 정의 금지.
6. **RLS 정책 안 서브쿼리는 SECURITY DEFINER 헬퍼로**(0051→0052 사고 교훈). 교차 테이블 조건은 `is_member_of`/`is_open_challenge` 패턴.
7. **200라인 규칙**: 새 탭·화면은 컴포넌트 분리 먼저 제안.
8. **정확한 식별자는 구현 직전 검증**: 이 문서가 언급한 테이블·함수명(참조수·응원·기부 등)은 실제 `mobile/lib/db.ts`·`supabase/migrations/`에서 **확인 후** 사용. 추정으로 코딩 금지.

### IA (결정 완료 2026-07-07)
- **탭바 재구성**: 생성(⊕)을 **우하단 플로팅 버튼(FAB)** 으로 빼고, 그 자리에 **파장** 독립 탭. 최종 하단 5탭 = `홈 / 내도전 / 파장 / 기록 / 해냈어요`, ⊕ = 우하단 FAB.
  - 구현: [`mobile/app/(tabs)/_layout.tsx`](../mobile/app/(tabs)/_layout.tsx) 탭 재정의(중앙 ⊕ 특수 탭 제거) + ⊕ FAB 컴포넌트(생성 라우트로 push). FAB는 스크롤/피드 본문 가리지 않게 위치·세이프에어리어 처리(Android edge-to-edge inset 주의 — 기존 함정).
  - 사상: **하단 탭 = 머무는 곳(dwell), ⊕ = 행동(action)** — IA가 깔끔해지고 파장 발견성 최대.
- **신규 화면**: `mobile/app/(tabs)/parang.tsx`(가칭) — 나의/우리의/세상 임팩트 3층. 200라인 넘으면 `components/parang/` 하위로 분리.

### 나머지 결정 (완료 2026-07-07)
- **우리의 파장 집계 주기 = 주간(이번 주)**. 월간은 갱신이 드물어 살아있는 느낌이 안 남.
- **나의 파장 익명 opt-out = W1엔 없음**. 나의 파장은 *본인만 보는 사적 대시보드* → 신원 노출 없음. 남에게 보이는 공개 항목이 생기면 그때 도입(후속).
- **3층 레이아웃 = 세로 스택(스크롤)**, `나 → 우리 → 세상` 순. 파장이 바깥으로 번지는 서사. 세그먼트로 쪼개지 않음.

### W1-b 파장 = 기여 피드 재설계 (2026-07-08, 승인·구현 중)
파장 v1(숫자 3장 대시보드)은 "매일 열 이유 없음"(존재가치 약함) → **기여 피드**로 재구성. 목업 승인. "자랑질과의 화해" = 소비 아닌 **기여를 나눔**(초대), 좋아요 없는 SNS.
- **구조**: 숫자 3장 → 상단 **슬림 헤더** / 아래 = **피드**.
- **피드 = 자동 이벤트 + 사용자 기여 글 (둘 다)**:
  - 자동(글 없이도 채움 = 허전함 해결): 🔁참조 파장(따라시작, 익명)·완주·기부 전환(gift donated). **기존 데이터 재활용**.
  - 사용자 글: 인증/기록 작성 시 **"파장에 나누기" opt-in 토글**(기본 OFF, 의도적 나눔만 — 무분별 크로스포스트 금지 = 피드 난립 방어).
- **다른 자랑 = 좋아요 없음**: `이 걸음을 따라 N명이 시작` **은은한 회색 한 줄**(움직인 사람 수, 참조수 0050 재활용). 반응 = **나도 할래요**(따라시작=create?ref=) + **용기받았어요**(0029). *좋아요 카운터·랭킹 없음.*
- **🎨 비주얼 규칙 (2026-07-08 지시)**: ① 이모지 대신 **하단 네비바와 같은 lucide 라인 아이콘**(이모지 과다 금지). ② **색 = tokens 기존 팔레트만, 신규 색 금지** — 응원 4색·평가(하다 둘러보기) 4색 = 8색 외 새 색 없음. 피드 본문은 **중립 + 브랜드 오렌지만**, 색은 반응에서만. (기존 파장 슬림헤더의 sage/gold 틴트도 중립화.)
- **⚠️ 중복 검토(사용자 지시)**: 기록(Vlog)·해냈어요(완주)와 겹칠 수 있음 → **구현 후 중복 크면 재검토.** v1은 파장 고유(참조 파장·기부 임팩트) 중심으로 차별.
- **스코프**: **v1 = 슬림 헤더 + 자동 이벤트 피드**(즉시 살아있음, 저위험). **v2 = 사용자 글 크로스포스트 토글 + 반응(나도할래요·용기받음)**.
- **구현 상태 (2026-07-08)**: **v1 코드 완료·검증(tsc 0)** — `0060_parang_feed.sql`(참조∪완주∪기부, 신원 미노출) + `fetchParangFeed` + `FeedCard`(lucide 아이콘·신규 색 0) + parang.tsx 재구성(WaveLayer 삭제). 배포 대기(⚠️ 0060 적용 → OTA). **중복 검토 결과**: donation·reference는 파장 고유, **completion은 해냈어요와 소재 겹침**(파장=익명 한 줄 신호 / 해냈어요=작성자·사진·반응 완결 목적지, altitude 다름) → **완주 유지(ⓐ 결정)**. **v1 배포 완료(0060 적용 + OTA preview·production).** **v2(사용자 글 크로스포스트 + 반응) 코드 완료·검증(tsc 0)** — `0061_parang_posts.sql`(proofs/logs `share_to_parang`·`parang_anon` + `parang_reactions` + `parang_posts()` RPC, 익명이면 author null) + `PostCard`(lucide·신규 색 0, 나도할래요=create?ref=·용기받았어요=toggle) + 인증/기록 작성 "파장에 나누기"+"익명" 토글. 배포 대기(⚠️ 0061 적용 → OTA).

## Phase W3 — 하다를 여는 3계층 무대 (명사 + 조직) 【무대 건설】

> **구현 상태 (2026-07-07) — Step 1 배포 완료 ✓**: `0058_host_tier.sql`(challenges.host_tier·host_label, 순수 additive, 운영 온보딩 SQL 수동만) 운영 적용 + `HostBadge`(현황 탭·홈 JoinCard 2곳) OTA preview·production. 배지는 운영자가 host_tier 지정 전엔 안 보임(무해). **Step 2(pod 연합)와 cap-exemption은 scale-gated 보류 — 아래 '착수 조건(트리거)' 참조.**

### 목적
개인 외에 **명사(선한 영향력 인물)**·**조직(기업/정부/NGO)**이 대규모 하다를 열 수 있게. 규모와 친밀함의 모순을 **pod 연합**으로 해결.

### W3-a. 계층·인증 (host tier)
- **DB**: `challenges.host_tier`(`'individual'|'figure'|'org'`, 디폴트 individual) — kind(참여구조: solo/cheered/closed/open)와 **직교**. 명사·조직 하다는 대개 open + verified host.
- **인증 주체**: 신규 `verified_hosts` 테이블 or `users.host_verified` + 배지 메타(이름·유형·아바타). **수동 온보딩만**(아무나 못 됨 — 큐레이션=품질, 메모리 `official-mission-type` 승계). 셀프서비스 신청 UI 금지(0단계).
- **게이트 승계**: 미성년 보호·내기 비활성 등 기존 규칙 그대로.
- **광고와 구분**: 명사/조직 하다는 회색 스폰서 배너가 아니라 **인증 배지 + 얼굴**로 노출.

### W3-b. Pod 연합 (규모 모순 해법 — 핵심 엔지니어링)
- 대규모 open/명사/조직 하다는 **거대 방 하나가 아니라 소수 pod들의 연합.**
- **DB**: `challenge_pods`(`id, challenge_id, seq`) + `challenge_members.pod_id`. 합류 시 **자동 배정**.
- **정원 모델 (결정 완료 2026-07-07)**: 친밀함을 규모와 무관하게 유지하려면 **pod 크기는 목표치 고정(~15~25명), 유동적인 건 'pod 개수'** — 10만 명이 들어와도 목격 단위는 항상 친밀. (크기를 키우면 결국 군중이 됨. 그래서 크기 아닌 수가 늘어남.) 초기엔 현재 pod를 목표치까지 채우고, 차면 새 pod로 split. 목표 크기는 상수 1개(`POD_TARGET_SIZE`)로 두어 운영 중 조정 가능(유동성 확보).
- **배정 = 관심 분류 기반 (결정 완료)**: 같은 관심(user_interests·challenge category)끼리 같은 pod로 묶어 **목격이 더 풍부하게**. 관심 매칭이 없으면 가장 안 찬 pod로 폴백.
- **경험**: 인증/대화/현황 탭은 **내 pod 기준**으로 목격(친밀·살아있음). 전체 운동 규모는 별도 배너("N명이 이 운동에 함께")로만 노출(비교 아님, 소속감).
- **0043 관계**: 누구나 방 모집 캡(0043)은 **개인 open** 전용 유지. 명사/조직은 캡 대신 **pod 무한 확장**(군중이 아니라 pod 연합이라 정체성 보존). 두 정책이 host_tier로 분기.
- **RLS**: pod 기반 가시성 = SECURITY DEFINER 헬퍼로(`is_member_of` 확장). 인증/기록 조회를 내 pod로 스코프.
- **주의**: 이건 **권한/가시성 로직** → 자동 테스트 의무 영역 인접. pod 배정·가시성 순수 로직은 테스트 권장.

### W3 착수 조건 — 언제 다음을 짓나 (결정 완료 2026-07-07: 🅰 scale-gated 보류)
결정: **pod는 조기에 짓지 않는다.** 명사/조직 하다는 지금 "배지 단 open 하다"로 운영. 섭외된 host가 0명인데 pod-스코프 RLS 대공사를 먼저 = 코드 부풀리기. 아래 조건이 **실재할 때만** 다음을 착수한다.

- **① cap-exemption — 첫 host 온보딩 시**: 현재 명사/조직 open 하다도 0043 모집 캡·자동마감을 그대로 받아 작게 유지됨(Step 1은 배지만, 행동 무변경). **첫 명사/조직 하다를 실제로 온보딩해 수백 명으로 키우려는 시점에** figure/org open 을 캡·자동마감에서 면제한다. 작은 변경: `stats.ts`의 `isRecruiting`/`recruitCloseAtMs`에 host_tier 예외 + `members_self_insert` RLS 가드 예외(0043 캡은 개인 open 전용으로 좁힘). 이때 crowd 감수 = OK(수백 명은 아직 목격 가능). 함께: 운영 SQL로 host_tier/host_label 지정 + 실기기 배지 확인.
- **② pod 연합 (Step 2) — 진짜 스케일 트리거** (아래 중 먼저 오는 것):
  - (a) 한 명사/조직 하다가 **~100명+ 활성**에 닿아 '목격하는 동료' 친밀함이 깨지기 시작(0043의 50·100 임계가 그 신호).
  - (b) 대규모 유입이 확실한 host(대형 팔로잉)를 **온보딩하기 직전**(사전 인지).
  - 착수 시 범위: `challenge_pods` + `challenge_members.pod_id` + 관심기반 자동배정(정원 ~15~25 고정·개수 유동) + pod-스코프 가시성 RLS(인증/대화/현황) + 전체 운동 배너. **완주·박제 pod별 vs 전체 판정도 이때 결정**(cheered 도전자 기준 로직 참고).
- **인증 온보딩 = 수동 운영 SQL 확정**(셀프서비스 UI 없음). 관리 화면은 host가 여럿 생겨 운영 부하가 실재할 때 후속.

### 검증
- **권한 테스트 필수**: pod 가시성(다른 pod 인증 못 봄), host_tier 게이트, 미성년 차단 승계.
- tsc 0 + `npm test`.
- 실기기: 1 pod / 여러 pod / pod 꽉 참→새 pod 생성 경계값.

### W3-c 상세 설계 — 명사 vs 조직 · 공식 미션 통합 · 스폰서십 (2026-07-07, 설계만·구현 보류)

> 사용자 요청으로 ⓐⓑⓒ 설계 구체화. **실제 구현은 W3 착수 조건 충족 시** — 지금은 방향만 확정.

#### ⓐ 명사(figure) vs 조직(org) — 무엇이 다른가
현재 코드는 배지 라벨만 다름. 아래로 성격을 분리(구현 시 반영):

| | 명사 (figure) | 조직 (org) |
|---|---|---|
| 주체 | 개인(선한 영향력 인물) — 얼굴·인격 전면 | 법인/기관 — 로고·기관명 전면(개인 얼굴 X) |
| 서사 | "이 사람과 함께 더 나은 내가" (팬→동료, 단 팬질 X·목격) | "사회에 기여하는 활동에 동참" (시민→기여자) |
| 톤 | 따뜻·인간적, 호스트가 함께 걷기도 | 공식·투명, 실제 세상 임팩트와 직결 |
| **내기** | 개인이라 기존 내기 파일럿 룰 승계 가능 | **절대 금지**(기관의 도박성 유도 = 규제·평판 리스크) → org 는 `bet_tier` 강제 null |
| **세상 기여** | 선택적 | **핵심** — 완주가 실제 기부/사회 임팩트로 (파장 탭 세상 임팩트 연결) |
| 온보딩 | 개인 신원 + 영향력 확인 | 법인 확인 (+스폰서십이면 계약) — 더 엄격 |
| 예 | 유재석 "함께 걷기 100일" | 환경부 "플로깅 30일" · 기업 "헌혈 릴레이" |

**핵심 차이 = 배지 라벨 + 내기 금지(org) + 세상 임팩트 연결(org) + 온보딩 엄격도.** 나머지 참여 경험(pod·목격·완주·박제)은 공통.

- ⚠️ **주최자 참여 구조 차이(데이터 모델)**: figure = 호스트가 도전자로 **함께 걸을 수 있음**(완주 대상 포함 가능). org = **주최자는 완주 대상 아님**(개설자=도전자 가정이 깨짐 — cheered 방처럼 주최자는 인증 안 하고 참여자만 인증). → org 하다는 host 계정을 완주·멤버·박제 집계에서 **제외**하는 처리 필요(구현 시 cheered 도전자-기준 로직 재활용).

#### ⓑ 공식 미션 = host_tier='org' (별도 challenge type 안 만듦)
기존 메모 `official-mission-type`(미션형·내기없음·✓인증배지·수동 온보딩)을 **host_tier 로 흡수** — 새 type 추가 금지(코드 부풀리기 방지):
- **✓ 인증 배지** = `HostBadge`(🏛️공식) 그대로. **내기 없음** = org `bet_tier` null(ⓐ와 일치). **수동 온보딩** = host_tier SQL 그대로.
- **미션 성격**(목표·기간 캠페인) = 기존 기간형/count형(0041) 재사용. 집단 목표 progress(예: "전국 10만 그루")가 필요하면 org 에 optional 캠페인 목표 필드 후속 → 그 집단 카운터는 **파장 탭 '세상 임팩트'로 흐름**.
- **결정 (2026-07-07): '공식(✓)' 배지 = org 전용.** figure = 자유로운 '운동'(목표·기간 자유) / org = 목표·기간 있는 '공식 미션'. 명사에는 ⭐명사 배지만, 공식 인증은 안 붙임.
- 결론: 공식 미션은 별도 시스템이 아니라 **org 하다의 성격**. → 메모 `official-mission-type` 갱신 대상.

#### ⓒ 스폰서십 모델 — "Sponsored good" (W4 상세로 승계)
**원칙**: 앱으로 광고비가 흐르는 게 아니라, 조직 후원이 참여자·사회의 선함으로 전환. *주목을 파는 광고가 아니라 선함을 후원.*
- **형태 1 — 완주 매칭 기부 (가장 하다다움)**: 조직이 "완주자 1명당 N원 ○○에 기부" 약정 → 완주 시 조직이 실제 기부. 개인 성취가 사회 기여로 증폭. 파장 세상 임팩트에 집계("여러분의 완주가 N원 기부가 됐어요"). **참여자↔돈 이전 0**(도박·결제 규제 무관), 조직→제3자 기부만.
- **형태 2 — 미션 후원**: 조직이 하다를 열고/후원하고 완주자에게 상품·인증서·굿즈.
- **형태 3 — 표시**: 조직 노출 = HostBadge + 안내문. **광고 배너 아님**(신뢰 표식).
- **광고(W4 다른 축)와 구분**: 스폰서십 = 무대 위 선함(콘텐츠 정합) / 광고 = 주변부 격리 슬롯(목격 피드 본문 오염 금지).
- **안전·순서**: 금전은 조직→기부처만(기존 기부 허브 `gift_orders` donated 인프라 결). 실제 정산·계약은 법무 게이트 후. MVP = 첫 조직 파트너 생기면 "완주 매칭 기부" 1형만 **수동 운영**(조직이 완주 수 보고 직접 기부, 앱은 집계 노출만) → 규모 커지면 자동화.

## Phase G — 글로벌화 (i18n) 【정식 기획 · W1부터 병행】

### 목적
